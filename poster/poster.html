01How the system works

Attacks like a deauthentication flood are not one strange frame — they are an abnormal burst of management frames from one device. So the system groups frames into 1-second windows per transmitter, measures a few simple things, and lets a classifier decide.

02The data

20 synthetic capture scenarios built with Scapy, each ~20 s of a small Wi-Fi network: an access point, 2–5 clients browsing and streaming, handshakes and power-save frames.

  • Normal traffic includes a few legitimate deauth/disassoc frames (a client leaving), so the model can't cheat with "any deauth = attack".
  • Attacks: broadcast flood, targeted flood, low-rate stealth flood, disassociation flood, rogue-MAC flood — each labelled per frame.
  • Every frame carries a RadioTap signal strength (dBm) and a ground-truth label.

Ethics: all frames are generated in memory and written to files. Nothing is transmitted over the air. Live capture / attack generation is for an authorised, isolated testbed only.

07What I'd improve

  • Train and validate on a real public dataset (AWID3) and on live captures from an authorised lab, not only synthetic traffic.
  • Add more attack classes: evil-twin / rogue AP, beacon flood, authentication flood, KRACK-style.
  • Make it multi-class (name the attack) instead of binary, and add a probability threshold to trade recall against false alarms.
  • Shrink the window / use overlapping windows to catch the first second of an attack (the current misses).
  • Stream features continuously and push alerts to a dashboard; rate-limit the auto-block and add a manual un-block.

An AI coding assistant (Claude Code) helped scaffold the Python modules, explain Scapy's 802.11 frame fields and the scikit-learn API, and draft this poster.

I made the design decisions myself: per-device time-window features rather than per-frame; including legitimate deauths in the normal class; and switching from a random split to a group split after noticing the random split leaked windows and inflated the score. I verified every number by running the code and reading the confusion matrix, and I can walk through how each part works in the demo.
